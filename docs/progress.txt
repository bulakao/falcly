## Codebase Patterns
- Profile table has a single row (id='local'); use `ensureProfile()` + `updateProfile()` helpers in userStore
- Drizzle migrations: SQL file in `drizzle/`, register in `drizzle/migrations.js` and `drizzle/meta/_journal.json`
- Snapshots in `drizzle/meta/` are not required for all migrations (only 3 exist for 7+ migrations)
- Settings screen sections follow pattern: groupLabel → SurfaceCard → content with dividers
- MoneyInput accepts `compact` prop for inline settings usage; use `parseMoney()` to convert formatted string to number
- Zustand setters always call both `updateProfile()` (SQLite) and `set()` (Zustand) for bidirectional sync
- `calculateSwipeImpact()` accepts optional strategy params at the end for backward compat; all existing callers work unchanged
- `computeMonthlyPayment()` is a pure helper — no store access, easy to unit test
