## Codebase Patterns
- Use `@/` path alias for all imports (maps to project root)
- Expo Router file-based routing: screens in `app/`, modal screens registered in `app/_layout.tsx`
- Zustand stores go in `store/` directory, one store per domain
- Types/interfaces go in `types/` directory
- Decision engine logic in `utils/decisionEngine.ts` — deterministic, first-match-wins evaluation
- Card status uses three channels: color (emerald/amber/crimson) + icon (✓/⚠/✕) + text label
- After adding new route files, Expo regenerates `.expo/types/router.d.ts` — run tsc after to verify
- Zustand persist with AsyncStorage: use `persist` + `createJSONStorage(() => AsyncStorage)` middleware, store name `falcly-cards`
- Swipe impact: `calculateSwipeImpact(card, amount, netAvailableCash)` in `utils/decisionEngine.ts` — netAvailableCash is null until CA stories
- Best card scoring: `scoreCard(card)` and `calculateBestCard(cards)` in `utils/decisionEngine.ts` — lowest score wins; cash penalty stubbed until CA
- Route params: use `useLocalSearchParams<{ paramName: string }>()` for typed params in Expo Router screens
- Cycle date math: `getCycleDates(card, today)` in `utils/decisionEngine.ts` returns cycleStart, statementClose, dueDate, and progress metrics
- New tab screens go in `app/(tabs)/` and must be registered in `app/(tabs)/_layout.tsx`
- Swipe-impact screen is the card detail screen — card-level actions (update balance, edit, delete) live here
- Staleness helpers in `utils/staleness.ts`: `formatUpdatedAgo()`, `getStalenessLevel()`, `daysSinceUpdate()`
- Staleness levels: fresh (<5 days), warning (5–9 days, amber), stale (10+ days, badge replaced)
- User profile store: `store/userStore.ts` with Zustand persist, store name `falcly-user`
- Cash on hand is `number | null` — null means not yet set; swipe impact shows "Not set" gracefully
- Net available cash is per-card: `computeNetAvailableCash(cash, income, payday, card, committedExpenses)` in `utils/decisionEngine.ts` — income included only when payday ≤ card due date, committed expenses deducted
- `calculateCardStatus()` accepts optional `netAvailableCash` param — pass it to enable cash-based RISKY detection on home screen
- `scoreCard()` and `calculateBestCard()` also accept net available cash — pass a getter function for per-card computation
- Projected balance formula: `projectedStatementBalance(card, proposedSwipe, today)` — canonical function, includes pending/installments/subscriptions/annual fee
- When adding new Card fields: add Zustand persist migration in `store/cardStore.ts` to backfill defaults for existing data
- Future cycle projections: `projectFutureCycles(card, netAvailableCash, today)` in `utils/decisionEngine.ts` — returns array of `FutureCycleProjection` with `isKnown` flag for signal-only cycles
- Onboarding flow: `app/onboarding.tsx` → `app/onboarding-result.tsx` → home; uses `router.replace()` to prevent back-nav to completed forms
- STATUS_EXPLANATIONS in `app/onboarding-result.tsx` — contextual one-sentence meaning for each status tier
- `StatusTooltip` component (`components/StatusTooltip.tsx`) — reusable dismissible tooltip for status badge education, uses Modal + backdrop pattern
- Subscription store: `store/subscriptionStore.ts` with Zustand persist, store name `falcly-subscription` — `canAddCard(count)` checks tier + card limit
- FREE_CARD_LIMIT = 2 — exported from `store/subscriptionStore.ts`
- Subscription state: `isPaidPro()` = paid subscriber, `isTrialActive()` = trial user, `tier === 'free'` = free user — use these helpers, not raw state checks
- Read-only cards: `isCardReadOnly(cardIndex)` checks free tier + index >= FREE_CARD_LIMIT — use to gate editing/reminders on expired Pro cards
- Data retention: `proExpiredAt` tracks when Pro expired; `daysUntilDataDeletion()` returns remaining days of 90-day retention window
- Network status: `useNetworkStatus()` hook from `hooks/useNetworkStatus.ts` — returns `{ isConnected, isOffline }`; `OfflineChip` component renders automatically in tab headers
- Firebase Firestore init: `initFirestore()` in `utils/firebase.ts` — call once at app startup; enables offline persistence with encrypted-at-rest cache
- Encryption: `encrypt()`/`decrypt()` in `utils/encryption.ts` — AES-256-GCM via `@noble/ciphers`; uses `.js` extension in imports (`@noble/ciphers/aes.js`)
- Cloud sync: `prepareCardForSync()`/`restoreCardFromSync()` in `utils/cloudSync.ts` — encrypts sensitive card fields before Firestore write
- Secure logging: `secureLog()`/`secureWarn()` in `utils/secureLogger.ts` — redacts sensitive financial fields; suppressed in production
